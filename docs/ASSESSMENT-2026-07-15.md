## Already have (verified — no action)
- **Credential vending**: on par with UC 0.4 / Polaris (per-table expiring creds, `/credentials` + `/commit` client-direct write; zero data bytes through the catalog).
- **Multi-warehouse physical tenancy** (#3-A + #35), soft-delete/undrop (stronger than Polaris/Lakekeeper minus timed expiration), per-table branches/tags/versions/time-travel, **atomic multi-table commit** (`batch-commit`), governed metadata **search tier-1** (shipped 2026-07-11, doc stale), discovery lists, model registry (#17/#42 — UC's registered-models equivalent, validator-gated promotion), blob-v2 multimodal + governed Range serving (our answer to UC volumes), table stats, maintenance mode, audit trail (#41), OpenLineage event stream.
- **Lineage**: still the moat — none of the five (Polaris events ≠ lineage; Gravitino's capture is nascent; Lakekeeper has zero) has versioned, storage-reconciled, column-level, FGA-governed lineage.

## N/A-by-design (do not build)
- Iceberg REST facade / Iceberg commit coordination (we operate Lance, not Iceberg pointers); functions/UDF management (UC, Gravitino — no SQL engine here); UC volumes as ungoverned file dirs (blob-v2 in-table is the deliberate alternative); OPA/Ranger/Cedar external-authorizer pluggability (OpenFGA is the committed engine, non-substitutable per the k8s/Dapr audit); geo-distributed metalake (Gravitino — wrong scale); inbound federation of Hive/JDBC/ClickHouse catalogs (we are a lakehouse catalog, not a metadata lake); presigned URLs (governed proxy chosen deliberately — signed URLs bypass ReBAC); multiple OIDC providers (Dex itself federates IdPs); metric views / semantic layer (blocked on native Lance MV/`base_objects`, already tracked); UC VARIANT type (Arrow-native types cover it).

**Bottom line**: no *obvious* table-stakes hole — vending, tenancy, refs, soft-delete, search, registry, and events are all present and lineage exceeds every competitor. The real gaps are governance-plane conveniences the 2026 crop converged on: writable business metadata, policy-driven maintenance (Lance version retention especially), generic-table interop, access review, and console breadth.

2. **No alerting engine at all** — confirmed: zero PrometheusRule/Alertmanager/rule-evaluator anywhere; the only trace is a Perses panel literally titled "alertable pair" (`perses-dashboards.yaml:148`). Nobody is paged when NATS dies, OpenBao seals, the outbox stops draining, or the DLQ fills. **Unnoticed.** Fix: GreptimeDB speaks PromQL (`/v1/prometheus`) — deploy vmalert (or Prometheus in rule-only mode) + Alertmanager with a real route; seed rules from the panels already labeled alertable (outbox depth/oldest-age, DLQ rate, error rate, NATS consumer lag, pod restarts).

3. **NetworkPolicy: zero objects in the prod render** — the full L3 layer (default-deny in/egress, DNS allow, exclusive client lists for openbao/age/rustfs) is *built* in `network-policy.yaml` but `networkPolicy.enabled` stays false and values-prod doesn't flip it.
