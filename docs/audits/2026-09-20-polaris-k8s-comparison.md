# What `antoniocali/polaris-k8s` has that rask does not (2026-09-20)

An external comparison, run as a 25-agent workflow: five dimensions surveyed against the upstream
repo, every candidate lesson then handed to an adversarial verifier told to refute it and to check
rask's own tree before accepting that rask lacks anything. **14 of 19 survived; 5 were refuted**, and
the refutations are the part worth reading first — three of them died because the finding's central
factual claim about rask was simply false.

## What the upstream IS, so the comparison is read correctly

`antoniocali/polaris-k8s` is a Kubebuilder-scaffolded Kubernetes operator, written in Go, that manages **Apache Polaris** (the REST Iceberg catalog) as Infrastructure-as-Code. It does not deploy Polaris — it reconciles resources *inside* an already-running Polaris server (the README explicitly contrasts itself with the official Apache Polaris Helm chart, which deploys the server). The whole Polaris management + catalog surface is modelled as **12 namespaced CRDs** in one group/version, `polaris.k8s.calific.io/v1alpha1`: `PolarisConnection` (server URL + OAuth client-credentials Secret), then `PolarisCatalog` → `PolarisNamespace` (self-nestable via `parentRef`) → `PolarisTable`/`PolarisView`/`PolarisPolicy`, plus the identity plane `PolarisPrincipal`/`PolarisPrincipalRole`/`PolarisCatalogRole`/`PolarisPrincipalRoleBinding`/`PolarisCatalogRoleBinding`/`PolarisGrant`. Each of the 12 reconcilers (`internal/controller/*_controller.go`) resolves its parent-ref chain, builds an authenticated Polaris HTTP client, does GET → create-or-PATCH → DELETE-on-finalize, and surfaces `Ready`/`Synced` (plus `AuthValid`, `CredentialsWritten`) conditions with `observedGeneration`. The Polaris HTTP client (`internal/polaris/`) is a hand-written facade — OAuth client-credentials token caching, TLS/CA-bundle config, a typed `APIError` with `IsNotFound`/`IsConflict`/`IsUnauthorized`/`IsRetryable` — wrapped around two large `oapi-codegen`-generated sub-clients built from **vendored** Apache Polaris 1.4.1 OpenAPI specs in `openapi/`. Testing is three-tier and unusually disciplined for a repo this young: per-reconciler unit tests against a `httptest.Server` fake Polaris, envtest specs against a real kube-apiserver (real CRD schema, status subresource, finalizer semantics) with only the Polaris backend faked, and a `test/e2e` suite that reconciles the full 12-kind graph against a **real** Apache Polaris container running as a sibling of the Kind cluster. There are two install paths with one source of truth: `config/` (kustomize, kubebuilder-owned) is authoritative, and `dist/chart/` + `dist/install.yaml` are *generated* from it and must never be hand-edited. Status is honestly declared alpha: all 12 reconcilers land, but there is no conversion webhook, no `spec.deletionPolicy` (delete always cascades to Polaris), and table/view schema/SQL drift is **deliberately** not reconciled — a documented permanent design decision, not a backlog item, on the grounds that schema evolution belongs to the data engine (Spark DDL, dbt), not a GitOps loop. The repo is three days old (created 2026-09-17), ~31 squash-merged PRs, 1 star, Apache-2.0, published as `ghcr.io/antoniocali/polaris-k8s` + `oci://ghcr.io/antoniocali/charts/polaris-k8s`, with a Zensical/MkDocs docs site at calific.io/polaris-k8s/.

**It is an Iceberg catalog's operator, and rask is Lance-only by permanent ruling.** So nothing here
is about adopting its data model; the verifier was instructed to refute any lesson that reduced to
"adopt Iceberg". What transfers is operational: how it proves its auth plane, how it guards
destructive targets, and how it keeps one source of truth for two install paths.
