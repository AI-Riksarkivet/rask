# Audit: `services/maintenance` (+ `service_kit.lakehouse` seams)

## 1. Credentials and blast radius

**Identity.** The sweep, orphan scan, reconciler and purge all run under one static key: `MAINTENANCE_S3_ACCESS_KEY_ID = .Values.rustfs.accessKey` (`chart/templates/maintenance.yaml:123`), which is `rustfsadmin` (`chart/values.yaml:1517-1518`; `:59` calls it "one pair for the Tenant credsSecret, the fleet AWS_*, and the lakehouse"). The secret is store-sourced via OpenBao when configured (`maintenance.yaml:124-130`; `config.py:246-257`), but it is still the estate root key — the RustFS `rolePolicy: readwrite`/session-policy narrowing (`values.yaml:1549`) applies to Dex-vended tokens, never to this key. It lists every bucket (`reconcile.py:362-373`) and can delete anywhere.

**What it can delete.**
- The sweep rewrites/reclaims in `sweep_buckets` ∪ every *active* registered warehouse bucket (`sweep.py:145-152`; `config.py:117-122`). The chart puts the medallion zone buckets AND `catalog.multibase.dataBases` (external/multibase data bases) into `MAINTENANCE_S3_EXTRA_BUCKETS` (`maintenance.yaml:142-149`), so external data bases are swept.
- The purge deletes `record["location"]` with `fs.delete_dir` (`purge.py:380-385`) if it sits under any maintained root at **bucket** granularity (`purge.py:237-253`, `_root_of` `:304-309`). Refusals: bare bucket root, control prefixes (`:332-340`), still-registered id (`:322-325`). It never checks the location is a Lance dataset dir — any sub-prefix of a maintained bucket named by a `_trash/` record is deletable. Records are trusted as written by the catalog (`trash.py:94-98`; trust-boundary note `maintenance_policies.py:22-25`).

**Registered `base_paths` — honoured, via a cross-estate pre-pass, with two holes.**
- Honoured: `base_refs.protected_roots` reads manifest field 18 of every discovered dataset (`features.py:112-117,159-198`) and the sweep refuses compact/optimize/cleanup on any protected root (`sweep.py:233`; `optimize.py:223-226`); purge refuses `delete_location` on one (`purge.py:571,375-379`). Pinned by `tests/unit/test_base_refs_guard.py:59-100,205-225`, including a cold-process proof that cleanup (not compaction) breaks the clone (`:137-150`).
- Hole 1 — coverage: referrers are collected only from datasets in the maintained set. A clone in a **deactivated** warehouse bucket (excluded by `warehouse_records.py:64`) or an unlisted bucket is invisible, so its source looks ordinary and is cleaned/purged. The module admits this (`base_refs.py:38-42`); `_estate_base_refs` degrades silently to "a floor, not a proof" (`purge.py:614-618`), and the sweep only warns on unreadable referrers (`sweep.py:236-244`).
- Hole 2 — granularity: `is_protected` is bidirectional containment (`base_refs.py:90`). An ingest-landed dataset registers its **whole source bucket** as a base (`ingest/adapters.py:296-306`, `lander.py:311-325` `initial_bases`), so once `LANCE_EXTERNAL_BLOB_BASES` approves it (`runtime.py:213-236`), `protected_roots` adds `<bucket>` and every dataset under that bucket is refused (compaction+cleanup+purge) — including the lakehouse itself if the source bucket is swept. Fail-safe, but silent beyond a per-dataset WARNING.

**Orphan scan vs shared/cloned bases.** Refuses flag 16, `tree/`, `_mem_wal/`, and any referenced-but-absent path (`orphans.py:294-323`), and is report-only (AST-gated, `tests/unit/test_orphan_files.py:192-212`). It cannot see the **source** side — scanning a clone's source reports files only the clone references as orphans (`orphans.py:289-292` says so).

**External blob objects under a registered base.** `cleanup_old_versions` is root-scoped and never touches them — measured, `.claude/skills/rask-lance-catalog/SKILL.md:248-256`; `lander.py:308-310`. They leak, they are not deleted; and because the dataset carries flag 16 the orphan scan refuses it, so nothing reports them either.

## 2. Branches, tags, clones

- **`tree/<branch>/` is never maintained.** `discover_datasets` stops at the first `_versions/` marker (`optimize.py:123-127`) and never descends into a dataset, so branch datasets are never compacted, index-optimized or version-cleaned; their history grows forever. Main-branch cleanup is branch-aware (Lance guarantee, `lance_docs/guide.md:4051-4053`; pinned `tests/unit/test_maintenance_optimize.py:96-126`).
- **Tags** are the GC exemption via `error_if_tagged_old_versions=False` (`optimize.py:385`; catalog `services/maintenance.py:95`). The sweep never reads tags itself; only the catalog preview enumerates them (`catalog/services/maintenance.py:53-61`). Tags live at root `_refs/tags/` regardless of branch (`lance_docs/file_format.md:2796-2816`) and the orphan scan skips `_refs/` (`orphans.py:382`). Whether Lance honours a tag that pins a *branch* version during main cleanup is moot since branches are never cleaned.
- **Cross-dataset pins** exist only for `base_paths` (clones/multibase) via the pre-pass; there is no cross-dataset notion of tags or lineage pins.
- **Clone when the source is cleaned:** clone breaks in a fresh process (`base_refs.py:9-21`). The sweep refuses the source; a **trashed** clone still protects its live source (`sweep.py:256-266`; `tests/unit/test_maintenance_trash_exclusion.py:127-165`). Clone itself: compaction refused (cost — materialises the base, `features.py:74-95`), cleanup + optimize allowed (`optimize.py:193-212`; `test_maintenance_optimize.py:480-516`).
- **The catalog's on-demand doors have no base-refs guard.** `run_gc`/`compact_now` only call `require_maintainable(ds)` on the target (`catalog/services/maintenance.py:21-35,91-124`); the source of a clone has flags `(0,0)` and no `base_paths` (`test_base_refs_guard.py:44-56`), so an owner clicking "reclaim" on it destroys the clone. The #114 fix closed the sweep, not this door.

## 3. Blob v2

- **Sizing:** global read bound `scan_batch_size=64` × `compact_threads=2` (`config.py:60,65`; chart `values.yaml:1176-1182`), per-tier `target_rows_per_fragment` bronze 512 / silver 262 144 / gold 524 288 (`tiers.py:47-57`), policy-overridable (`sweep.py:323-326`). Tier is inferred from path convention only (`tiers.py:94-132`); a blob table in an untiered namespace gets Lance's default fragment sizing (batch bound still applies).
- **`.blob` sidecars in the orphan scan:** `data/<stem>/` is marked referenced when its `.lance` is (`orphans.py:191-202,376-378`); pinned by `services/maintenance/tests/test_orphans_spare_live_data.py:86-94` and `test_orphan_files.py:276`. Sidecars whose `.lance` is gone are reported (`orphans.py:200-202`) — the claim that Lance cleanup leaves the sidecar is stated, not tested.
- **Repacking packed sidecars:** nothing. `compact_files` is called without `compaction_mode` (`optimize.py:254,277`; pylance 10 exposes `reencode|try_binary_copy|force_binary_copy`, `.venv/.../lance/dataset.py:7041-7042`); no code, metric or test addresses blob repack, and whether compaction rewrites dedicated blobs is neither measured nor pinned (docs only: `lance_docs/guide.md:571-574`).

## 4. Scheduling and single writer

- **Trigger:** two Dapr `bindings.cron` components (`chart/templates/maintenance.yaml:9-38`), `@every 120s` sweep / `@every 300s` reconcile (`values.yaml:1153,1158`), POSTing `/<binding>` gated by `require_dapr_token` (`routes.py:171-191`; `dapr_auth.py:70-100`).
- **Concurrency:** process-local `asyncio.Lock`, skip-don't-queue (`routes.py:61,73-76,92,112-115`); replicas hard-coded `1` (`maintenance.yaml:47`) and pinned by `tests/unit/test_invariants.py:4235-4267`. No lease. The Deployment sets no `strategy` (`maintenance.yaml:41-66`) so a RollingUpdate surges a second pod while the old one finishes a sweep under a 120 s grace (`:63`; `values.yaml:514`). The catalog's on-demand compact/run doors also run with no coordination against the sweep. Sweep and reconcile locks are independent (`routes.py:61,92`).
- **Half-finished purge:** per-record revoke→delete→clear, each idempotent (`purge.py:14-24,437-478`); no persisted progress; 25/tick oldest-first (`:559-561`). **No attempt counter or last-error on the record** (record fields `trash.py:80-91`; refusals only logged/returned `purge.py:442-445`). A permanently refused record retries every 300 s forever and keeps its dataset frozen forever (`sweep.py:204-206`).
- **Half-finished sweep:** no resumption; order shuffled so a crash point rotates (`sweep.py:283`); started/completed counters (`sweep.py:117-120,385`).
- **Read-only mode:** `LANCE_MAINTENANCE_READ_ONLY` is a catalog HTTP write gate only (`catalog/api/maintenance_mode.py:46-55`, `catalog/core/config.py:285`). The sweep neither reads it nor tells the catalog anything; Lance optimistic commits are the only coordination.

## 5. Authorization and audit

- Service routes: Dapr token only, no FGA, not routed by the gateway (no `maintenance` in `services/gateway`).
- Catalog doors `/v1/table/{id}/maintenance/{preview,run,compact}` → `can_drop` (`catalog/api/fga_deps.py:138-142`; `endpoints/maintenance.py:24-56`). `can_drop: owner` (`model.fga:351`), owner cascades namespace→warehouse→`admin from project` (`model.fga:257,96`), so a project admin can compact any table in their project and only there — correct. No test exercises those three suffixes (grep empty).
- **Audit of GC:** sweep emits one aggregate summary log (`routes.py:80`; `summarize` `sweep.py:486-524`) — per-dataset versions/bytes removed are never logged. The catalog doors log nothing and emit no control event (`endpoints/maintenance.py` has no logger/emitter). Purge is the only well-audited path: `trash_purged` WARNING (`purge.py:491-494`), control event `table_purged`/`namespace_purged` actor `service:maintenance` reason `trash_expired` (`:421,495-508`), revoke audited with origin `lifecycle_delete` (`:399`; `fga.py:1089`). `dropped_by` is on the record (`trash.py:85`) but not carried into the log/event.

## 6. Lineage

- Emits OpenLineage COMPLETE (`operation=compaction`, versionless, no inputs) per materially changed dataset and a deterministic-run-id FAIL per `maintain:` error (`lineage_emit.py:85-116,169-188,226-256`; `sweep.py:417-483`). Only for `<uuid>_<table_id>` layout or a stamped `lineage.dataset_id` (`sweep.py:451-454`; `lineage_emit.py:135-166`); medallion tiers emit nothing unless stamped (`values.yaml:1200-1212`).
- Purge and reconciler consult no lineage (no `lineage` in `purge.py`/`reconcile.py`); the reconciler writes nothing (AST gate `tests/unit/test_reconcile_report.py:505-515`). A purge emits a control event, not a lineage event.

## 7. Dapr coupling

Used: `bindings.cron`×2; `pubsub.jetstream` publish-only ×2 (`dapr-component.yaml:19-23,44-51`); secret store (`config.py:198-203,246-257`; `dapr-component.yaml:305-306`); app-token header. Not used: state store, actors, subscriptions, service invocation.
Dapr-free replacement: an in-process scheduler or JetStream scheduled/republished message per tick; a JetStream KV entry with TTL (or an S3 `If-None-Match` lock — `service_kit.lakehouse.records.create_json` already exists) as the sweep lease; direct `nats.js.publish` behind the existing `MaintenanceEmitter`/`ControlEmitter` protocols (`lineage_emit.py:191-197`); OpenBao HTTP for the secret.

## 8. Tests

Pinned: trash exclusion + positional trap; base-refs pre-pass incl. cold-process proof and a real sweep tick; purge refusal ladder; orphan false positives (tags/marker/sidecar/manifests/live txn); branch-aware main cleanup; clone compaction refusal + GC allowed; unknown-flag refusal; single-flight; replicas=1 invariant; read-only AST gates; session sharing; policy resolution.
Untested: **no test proves cleanup on a dataset sharing a base with a live sibling spares the sibling** — `test_base_refs_guard` covers only a shallow clone whose source is *refused*, never a cleanup actually run against a shared non-root base (grep for shared-base tests: empty). Also untested: catalog on-demand doors vs a clone's source; sidecar left behind after cleanup; an external-base (flag 16) dataset through sweep/scan/purge gating; deactivated-warehouse referrer; FGA on the three doors; anything against RustFS (#80 open, `purge.py:50-54`).

## 9. Top 5 findings

1. **HIGH — on-demand `/maintenance/run` and `/compact` destroy live shallow clones.** `catalog/services/maintenance.py:91-100,103-124` gate only on the target's own flags; the source carries none (`test_base_refs_guard.py:44-56,137-150`). Fix: apply `base_refs.protected_roots` (or a catalog-side clone-source registry) before both calls, as `optimize.py:223-226` does.
2. **HIGH — approved external blob bases make purge unreachable and refuse whole buckets.** Ingest registers the source *bucket* as a base (`adapters.py:305`, `lander.py:311`): flag 16 → orphan scan refuses (`orphans.py:294-295`) → `incomplete` (`reconcile.py:757-758`) → `report_is_clean` blocks every purge (`purge.py:223-224`); and `protected_roots` adds the bucket root so every dataset under it is refused (`base_refs.py:90`). Fix: parse `BasePath.is_dataset_root` (field 3, `features.py:113-114`) and treat non-dataset-root bases as neither scan-refusing nor protecting.
3. **MEDIUM-HIGH — clone protection is bounded to maintained buckets.** A referrer in a deactivated warehouse (`warehouse_records.py:64`) or unlisted bucket is invisible (`sweep.py:145-155,233`; `purge.py:612-631`), so its source is cleaned/purged. Fix: collect referrers over all registered buckets including deactivated (as `reconcile.py:715-721` already scans) and refuse the tick if any bucket's discovery fails.
4. **MEDIUM — single-writer and retry state are process-local and unpersisted.** No lease (`routes.py:61`), no `strategy` on the Deployment (`maintenance.yaml:41-66`), catalog doors uncoordinated; refused trash records carry no attempts/last-error (`trash.py:80-91`, `purge.py:442-445`) and freeze their dataset indefinitely (`sweep.py:204-206`). Fix: a conditional-put lease per tick (and per dataset for the catalog doors) via `records.create_json`, plus `attempts`/`last_refusal` persisted on the record.
5. **MEDIUM — version GC has no per-object audit trail.** The sweep logs only totals (`routes.py:80`; `sweep.py:486-524`); the catalog doors log/emit nothing (`endpoints/maintenance.py:39-56`). Fix: per-dataset structured log + a `table_maintained` control event (actor, versions_removed, bytes_removed) from both the sweep and the doors.

Also notable: branch datasets under `tree/` are never maintained (storage leak, `optimize.py:123-127`); purge will `delete_dir` any sub-prefix of a maintained bucket a trash record names, dataset or not (`purge.py:326-340,380-385`); everything runs as the RustFS root key (`maintenance.yaml:123`, `values.yaml:1517`).
