# Audit: `services/lineage` + `packages/lineage-kit`

## 1. INGESTION

**Three doors into the graph, one repository method behind all of them** (`LineageRepository.ingest_event`, `services/lineage/src/lineage/services/repository.py:473-653`):

| Door | Route / trigger | Auth | Who uses it |
|---|---|---|---|
| HTTP | `POST /api/v1/lineage` (`api/v1/endpoints/ingest.py:244-271`), proxied by the gateway as `/api/lineage/api/v1/lineage` (`services/gateway/.../main.py:145`) | OIDC bearer **or** the service door (`dapr-api-token` + `x-lance-service-identity`, `api/security.py:433-485`); `enforce_author` (`fga_deps.py:96-104`) + `enforce_output_authz` (`fga_deps.py:144-230`) | catalog when `LANCE_LINEAGE_TRANSPORT=http` (code default, `catalog/core/config.py:307`; chart sets `dapr`, `services.yaml:114`), every `lineage-kit` `ClientEmitter` (medallion compute, ingest, annotator publish, Ray TRAIN), external OpenLineage producers |
| Bus | Dapr subscription `lineage.events.v1` → `POST /lineage-events` (`api/dapr.py:302-355`) | `require_dapr_token` only (`service_kit/governed/dapr_auth.py:70-102`); **no** `enforce_author`, **no** FGA (`services/consumer.py:33-35`) | catalog (dapr transport), maintenance compaction, medallion producer/movers (via outbox) |
| Reconcile | (a) cron binding `POST /lineage-reconcile-cron` (`api/reconcile_cron.py:249-362`) — version/schema back-fill via `backfill_write` (`repository.py:1078-1145`) + outbox drain that re-calls `ingest_event` (`reconcile_cron.py:365-420`); (b) `POST /api/v1/admin/dlq/{run_id}/replay` (`endpoints/dlq.py:679-735`) | (a) `require_dapr_token`; (b) OIDC + `enforce_output_authz` | operator / scheduler |

**Spec conformance on the wire in** (`services/lineage/src/lineage/models.py`): `RunEvent` requires only `eventType`, `eventTime`, `run.runId`, `job.{namespace,name}` (`models.py:318-328`, `277-282`). `eventType` is a bare `str` — no enum check, so `"COMPLETED"` or `"complete"` is accepted and stored (`is_success` upper-cases, `models.py:424-426`, but `_DATASET_LAST_SUCCESS_OP` compares `r.event_type = 'COMPLETE'` case-sensitively, `repository.py:268-270`). `runId` is not validated as a UUID; `eventTime` is a free string (every ORDER BY and the retention cutoff rely on it being ISO-8601 UTC, `repository.py:306-309`). `schemaURL` and `producer` are optional. `extra="allow"` throughout (`models.py:14`).

Facets actually read: run `author` (custom; `name` preferred over `sub`, `models.py:331-350`), `lance` (custom: `operation`, `run_id`, plus `version/project/originator/token` that lineage ignores but notifications reads), `errorMessage`, `progress` (custom), `parent` — **parsed (`models.py:362-404`) but never written to AGE** (no repository reference; grep confirms). Job: `sourceCodeLocation`, `ownership`. Dataset: `version`, `dataSource`, `schema`, `columnLineage`, `outputStatistics`, `dataQualityAssertions`, `tags` — looked up across `facets`/`inputFacets`/`outputFacets` (`models.py:77-93`). Schema versions pinned: envelope 2-0-2, ParentRun 1-2-0, ErrorMessage 1-0-1, Schema 1-2-0, OutputStatistics 1-0-2, Datasource 1-0-1, DatasetVersion 1-0-1, ColumnLineage 1-2-0 (`lineage_kit/schemas.py:554-567`, `service_kit/openlineage.py:30-52,111`), asserted against the installed client by `packages/lineage-kit/tests/test_spec.py:100`.

**Idempotency.** Every vertex/edge is MERGEd: Run on `run_id`, Dataset on `name`, Job on `(namespace,name)`, Column on `(dataset,field)` (`repository.py:88-110, 255, 392-394`), backed by UNIQUE functional indexes (`repository.py:240-244`, `ensure_graph_constraints` :1217-1247; chart `age-postgres.yaml:24-33`). Feed rows dedup on `(run_id,event_type,event_time)` + a partial unique on `(run_id,event_type)` for terminal types (`repository.py:159-188`). Exact redelivery converges (pinned by `tests/unit/test_lineage_dapr_delivery.py:181`, `tests/e2e-py/test_lineage_e2e.py:452`). `Run.events_count` is a plain delivery counter (documented, `repository.py:95-97`).

**Out-of-order is NOT handled.** `_MERGE_RUN` sets `event_type`/`event_time`/`author`/`producer`/`error_message` last-delivery-wins (`repository.py:98-110`). A START (or RUNNING) arriving after COMPLETE — the outbox drain and DLQ replay both re-ingest arbitrarily old events (`reconcile_cron.py:407`, `dlq.py:727`) — regresses `event_type` to `START`; the WROTE edge/version survive (SET only under `is_success`, :581-588) but `dropped_at()` (`:883-897`) and `_fold_writes` (`:443-453`) key on the terminal type, so a regressed `drop_table` run re-enters the reconcile sweep and `/runs` shows the run as live forever. No test covers this (grep for reorder/out-of-order in `tests/unit/test_lineage*.py`, `tests/e2e-py/test_lineage_e2e.py` finds only redelivery-of-identical cases).

**Rejected vs silently accepted.** HTTP: pydantic failure → 422; FGA/OIDC → 401/403/503 (`fga_deps.py:50-63`). Bus: pydantic failure → `DROP` (acked, `consumer.py:438-443`); any other exception → `RETRY`. Silently accepted: unknown event types, non-UUID run ids, malformed `progress`/`parent`/`columnLineage` items (dropped item-by-item, `models.py:143-157, 406-421`), schema facets >512 fields (truncated at the emitter, `service_kit/openlineage.py:87-105`), tags containing commas (rewritten to `_`, `repository.py:688`).

## 2. DURABILITY

- **HTTP door is durable-before-ack for the graph only**: `ingest_event` runs in one transaction (`repository.py:475`) and the 201 follows it; the `lineage_events` feed row is written *after*, best-effort, outside that transaction (`ingest.py:264`, `consumer.py:424-430`). The bus door returns `SUCCESS` even when the feed insert failed (`consumer.py:445-454`). So `GET /events` — the feed notifications replays (`services/notifications/api/reconciler.py:257`) — is provably a subset of the graph; an event can be in AGE and never reach anyone's inbox.
- **Bus is at-least-once with a bounded retry then park**: sidecar retries 30/60/120/240 s (`chart/templates/dapr-resiliency.yaml:29-45`), then dead-letters to `dlq.lineage.events` (`services.yaml:323`), where `/lineage-dlq` only ERROR-logs + acks (`api/dapr.py:313-335`). Recovery is "restart the pod": the main consumer is `deliverPolicy=all` **and ephemeral** (`dapr-component.yaml:161-172`), so every pod restart replays the whole 168 h stream (`nats-stream-job.yaml:59`) through the serial per-event MERGE path.
- **AGE down**: HTTP producers lose the event outright — catalog `HttpLineageEmitter` and `lineage_kit.ClientEmitter` both swallow (`catalog/core/lineage_emit.py:598-604`; `lineage_kit/emitter.py:193-197`); only the medallion stages events through the object-store outbox first (`medallion/services/produce.py:140`, `service_kit/lakehouse/outbox.py:177`). Bus producers survive an outage < 7.5 min; longer and every event published in the window is parked on the DLQ with no automatic replay. `/readyz` pulls the pod from Service routing (`main.py:146-168`) but the sidecar keeps delivering to the app port, so parking still happens.
- **Reconcile sweep** (`core/reconcile.py:144-206`, every 300 s, `values.yaml:388`): iterates `list_datasets()` **from the graph**, skips any node without `source_uri` (`:170-172`) and any `dropped_at` node (`:173-177`); back-fills only `STORAGE_AHEAD`/`UNTRACKED` (`:135, 199-204`) as a synthetic `RECONCILED` run carrying version + on-disk schema and `author='reconcile'`, no inputs, no `DERIVED_FROM`, no column lineage (`repository.py:1086-1088`). Consequence confirmed: **a lost `create_table`/`declare_table`/`register_table` is unrecoverable** — the Dataset vertex (and its `dataSource` URI) is created only by that event, and the sweep enumerates the graph, not storage; a lost subsequent write on a known table is back-filled version-only; a lost `drop_table` makes the sweep WARN `missing_on_storage` on every tick forever (`reconcile_cron.py:320-323`). The outbox drain (`reconcile_cron.py:365-420`) recovers full events, but only for producers that use the outbox (medallion), bounded 500/tick.

## 3. GRAPH MODEL

Node labels `Job`, `Run`, `Dataset`, `User`, `Column`; edges `OF_JOB`, `READ {version}`, `WROTE {version, schema, row_count, size_bytes, quality_passed, quality_assertions}`, `DERIVED_FROM`, `CREATED {created_at}`, `HAS_COLUMN`, `DERIVED_FROM_COLUMN {transformation_type, subtype, masking, description, run_id, output_version}` (`repository.py:8-21, 280-332, 392-413`).

- **Versions are edge properties, not nodes**: one `WROTE` edge per (run, dataset) via MERGE (`:287`), so a run cannot record two versions of one table; the "current version" is the newest-by-`event_time` `WROTE.version` (`_LATEST_WRITE_VERSION` :352-354), a string compared as `int` at read (`:881`). Schema-at-version is a JSON string on that edge (`:321`).
- **Branches / tags / shallow clones / multi-base: not representable.** `version` is a bare integer with no branch qualifier; reconcile reads `lance.dataset(uri).version` (main only, `core/reconcile.py:42`); the catalog's `branches.py`, `tags.py`, `versions.py`, `transactions.py` emit nothing (grep `emit_` = 0). `promote_model` (tag move) is emitted as a versioned WROTE at the *target* version (`lineage_emit.py:102-106`), so it is indistinguishable in the graph from a write that minted that version.
- **Column lineage**: `Column` MERGEd on `(dataset, field)` — one node per column for all time; `DERIVED_FROM_COLUMN` MERGEd per (out,in) pair with props overwritten last-wins (`:404-413`), so field-level lineage is *latest only*, not per run/version. `HAS_COLUMN` is pruned to the newest schema facet (recency-gated, `:655-666, 726-732`).
- **Dataset identity = catalog canonical id** (`alpha$bronze$images`, `lineage_emit.py:734-736`), namespace and `source_uri` SET last-wins (`:255-258`); external sources are keyed `namespace/name` (`models.py:17-26`). **Rename** = source gets a versionless `drop_table` run, destination is a *new* vertex with `register_table` + `DERIVED_FROM` source + a fresh `CREATED` (`catalog/.../tables.py:788-857`); all prior `WROTE` history, schemas, column edges stay on the old id — `/schema`, `/producers`, `/columns` for the new id are empty until the sweep back-fills a schema-only reconcile run. **Move without rename** (re-register) overwrites `source_uri` in place; the old location is not recorded.
- **Run hierarchy from lineage-kit is dropped**: `job_run`/`@stage`/`LineageActorMixin` emit `parent` facets (`lineage_kit/runs.py:411`, `context.py:411-420`) that the consumer parses (`models.py:362-404`) and never persists — every stage/actor run lands as an unattached root in `/runs` and `/jobs`.

## 4. AUTHORIZATION

Query surface (all under `/api/v1`; FGA object `table:<name>`, `config.py:60`):

| Endpoint | Gate |
|---|---|
| `/datasets/{name}/{upstream,downstream,producers,creator,schema,graph,columns,columns/{f}/{up,down}stream,governance,reconcile}` | `can_get_metadata` on `{name}` (router deps `datasets.py:21-25`, `columns.py:547-551`, `reconcile.py:460-464`, `governance.py:462-466`); related nodes batch-filtered by `DatasetFilter.visible` (`fga_deps.py:233-265`) |
| `/datasets/{name}/readers` | `can_get_metadata` **and** `can_write_data` (`datasets.py:56`) |
| `PUT/DELETE /datasets/{name}/tags/{tag}`, `PUT .../description` | `can_write_data` (`governance.py:467-471`) |
| `/datasets`, `/search`, `/graph`, `/jobs`, `/namespaces`, `/runs`, `/runs/{id}/inputs`, `/events` | fetch-all then `governed()` drop (`fga_deps.py:276-295`); dataset-less rows hidden when FGA on |
| `/admin/dlq` list/replay | token required; per-dataset visibility; replay re-runs `enforce_output_authz` (`dlq.py:664-675, 720-726`) |

So: a subject cannot see lineage of a table it cannot `describe`; there is no separate lineage relation in `model.fga` (`can_get_metadata: reader` at `service_kit/governed/auth/model.fga:342`). Gaps: `/events?summary=true` governs on bare names and therefore *over*-hides external-input rows (documented, `runs.py:353-355`); `/producers` returns `author`/`error_message` for every run that touched a table the caller can merely read; `/readers` (who-read-what) is gated on `can_write_data`, i.e. any writer, not owner. Write door: HTTP requires `can_write_data` on outputs, `can_get_metadata` on governed inputs and column upstreams, and on any output a *pre-existing* run already recorded (`fga_deps.py:184-230`); the bus door trusts the producer-stamped `author` entirely behind one shared `APP_API_TOKEN` (`dapr.py:302-310`), with the gateway 403-blocking `/api/lineage/lineage-events` and the cron route (`gateway main.py:211-218, 289-299`). All auth is default-OFF (`config.py:43, 53`) and the chart turns it on (`services.yaml:368-375`).

## 5. RETENTION / SCALE

Per Lance commit through the catalog: 1 `Run` vertex + `OF_JOB` + N `READ` + M `WROTE` (each carrying the full schema JSON, stats and assertions) + `Job`/`Dataset` MERGE round-trips (~12–30 serial Cypher statements per event, `repository.py:476-653`) + one `lineage_events` row holding the entire event JSONB. Feed retention 20 000 rows by default, pruned by a `DELETE` on **every** insert (`config.py:164`, `repository.py:1295-1296`) — at a commit every few seconds the feed covers ~1 day, and the notifications reconciler detects the resulting gap via `oldest_seq` (`runs.py:425`, `notifications/.../reconciler.py:382`). **Run retention is off by default** (`values.yaml:404`, `config.py:170`); when on, batched DETACH DELETE of 500 under the cron lock (`repository.py:1147-1163`), which also deletes per-version schema history.

Indexes: unique functional on `Run.run_id`, `Dataset.name`, `Job(namespace,name)`; plain on `Column(dataset,field)` (`repository.py:240-252`). Nothing on `Run.event_time` (the retention predicate and every `ORDER BY r.event_time DESC`), nothing on edge properties. Query cost: `_PRODUCERS` (`:340-348`), `_LATEST_WRITE_VERSION` (`:352-354`), `_DATASET_LAST_SUCCESS_OP` (`:268-270`) and `_SCHEMA_LATEST` each sort the full WROTE history of a dataset — O(history) per call, and `_schema_is_current` runs `_LATEST_WRITE_VERSION` **on every ingest with a schema facet** (`:660, 711`), so ingest latency grows linearly with a table's commit count; the sweep runs `latest_write_version` + `dropped_at` per dataset per 300 s. `_LIST_RUNS`, `_ESTATE_WRITES`, `_ESTATE_NODES` are fetch-everything, unpaginated (acknowledged at `:123-131`). `/graph` caps nodes at 500 but reads all edges/writes first (`discovery.py:223`). `upstream`/`downstream`/column traversals are unbounded `*1..` (`:334, 339, 414-419`); the only bound is the 30 s `statement_timeout` (`core/age.py:509`, `config.py:40`) → a timeout surfaces as a 500. Pool `max_size=8` (`age.py:507`). AGE 1.5.0 on PG16 single StatefulSet by default (`values.yaml:2089`, `age-cluster.yaml` opt-in HA); pg_dump backup CronJob (`backup-pg.yaml:57`).

## 6. DAPR COUPLING and STATE

Blocks used: pub/sub subscription via `dapr.ext.fastapi.DaprApp` (`api/dapr.py:348-366`) on a per-app JetStream component (`dapr-component.yaml:172-236`) + DLQ component (`:238-267`); `bindings.cron` for the reconcile sweep (`services.yaml:216-233`, `reconcile_cron.py:428-433`); the `lance-secrets` Vault secret store for S3 + DB password and per-service credentials (`config.py:216-231`, `security.py:413`); the app-api-token / `dapr-caller-app-id` headers as the auth primitive for both sidecar routes and the service door. **No state store, no actors, no outbound service invocation, no workflow.** Lineage's own state is entirely Postgres (AGE graph + `lineage_events` + `lineage_reads` + the advisory lock `repository.py:234, 1249-1266`). Replacement is mechanical: a nats-py durable pull consumer (the ingest service already does this, `nats-stream-job.yaml:66`), a k8s CronJob or in-process scheduler for the sweep, a mounted secret or Vault client, and mTLS/JWT for the service door.

## 7. GOVERNANCE USES

- **GC pins: none.** Maintenance imports only `lineage_emit` (`maintenance/services/sweep.py:24`); `purge.py`, `optimize.py` and the catalog trash path make no lineage query. `READ.version` pins recorded for training (`repository.py:284, 566-576`) are never consulted before `cleanup_old_versions`/purge, so a pinned feature version can be reclaimed while the graph still cites it — the sweep would then report `GRAPH_AHEAD` (`reconcile.py:141`) as a warning only.
- **Erasure propagation: dataset/column granularity only.** `/datasets/{name}/downstream` and `/columns/{field}/downstream` answer "which tables/columns derive from this table/column" (`repository.py:776-779, 807-814`); there is no row- or blob-level edge in AGE. Row provenance rides inside the tier tables (`lineage_kit/consume.py:92-115` `LineageDoc` JSONB; `source_rowid` in `medallion/schemas/tier.py`), so "which datasets contain derivatives of *this* row/blob" needs a Lance scan per downstream table, not a graph query.
- **Audit.** Write audit = AGE graph + `lineage_events` — but events are best-effort at every producer (`catalog/.../lineage_emit.py:8-11`), the feed is a lossy projection (§2), and `RECONCILED` back-fills carry `author='reconcile'`, so it is a provenance log, not a complete write-audit log. Read audit: `lineage_reads` (`repository.py:215-224, 1303-1321`) records only reads of **lineage's own** endpoints (`fga_deps.py:80-93`, router deps), never catalog/explorer data reads; it has no index on `dataset`, no retention, and the chart enables it by default under auth (`services.yaml:389`). It cannot serve as the estate's read-audit log.

## 9. FIVE MOST CONSEQUENTIAL FINDINGS

1. **HIGH — Lost origination events are unrecoverable and invisible.** `reconcile_all` enumerates `repository.list_datasets()` and skips nodes without `source_uri` (`services/lineage/src/lineage/core/reconcile.py:169-172`), while every HTTP producer swallows failures (`services/catalog/src/catalog/core/lineage_emit.py:598-604`, `packages/lineage-kit/src/lineage_kit/emitter.py:193-197`). *Fix:* make the sweep enumerate storage (the catalog registry / warehouse roots, as `maintenance` already does) and create the Dataset vertex from the on-disk `lineage.dataset_id` metadata (`catalog/core/lineage_metadata.py`), so an unknown table becomes `UNTRACKED` instead of nonexistent.

2. **HIGH — Bus door trusts a producer-stamped author behind one shared token.** `/lineage-events` runs neither `enforce_author` nor FGA (`services/lineage/src/lineage/api/dapr.py:302-310`; `services/consumer.py:33-35`), and `APP_API_TOKEN` is shared by every sidecar app plus seven sidecar-less web pods (`services/lineage/src/lineage/core/config.py:70-79`). *Fix:* have the subscriber verify a producer signature (or per-publisher Dapr scoped tokens) and apply `enforce_output_authz` as the stamped subject, exactly as the HTTP door does.

3. **MEDIUM — Last-delivery-wins run state regresses on out-of-order ingest.** `_MERGE_RUN` overwrites `event_type` unconditionally (`services/lineage/src/lineage/services/repository.py:98-110`); the outbox drain and DLQ replay feed arbitrarily old events (`api/reconcile_cron.py:407`, `api/v1/endpoints/dlq.py:727`), and `dropped_at`/`_fold_writes` key on that field (`:268-270, 443-453`). *Fix:* make the terminal state sticky (`CASE WHEN r.event_type IN terminal THEN r.event_type ELSE $et END`) or compare `event_time` before SET, and pin it with a START-after-COMPLETE test.

4. **MEDIUM — `GET /events` is not a faithful replay of the graph, yet notifications depends on it.** The feed insert is best-effort after the graph commit on both doors (`services/lineage/src/lineage/api/v1/endpoints/ingest.py:261-264`, `services/consumer.py:445-454`) and pruned to 20 000 rows on every insert (`repository.py:1295-1296`; `config.py:164`), while `notifications` reconciles solely from it (`services/notifications/src/notifications/api/reconciler.py:257`). *Fix:* write the feed row inside `ingest_event`'s transaction (same connection, same commit) and size retention in time, not rows.

5. **MEDIUM — Unbounded growth with O(history) hot paths and no default pruning.** `runRetentionDays: 0` (`chart/values.yaml:404`), `_LATEST_WRITE_VERSION` sorts a dataset's entire WROTE history and is executed on every schema-bearing ingest via `_schema_is_current` (`repository.py:352-354, 660, 711`), `/runs` and `/graph` fetch every node/edge (`:119-138, 380-385`), no index on `Run.event_time`, traversals bounded only by a 30 s statement timeout (`core/age.py:509`). *Fix:* store `latest_version` on the Dataset node (SET when a newer version lands), add a functional index on `Run.event_time`, cap variable-length paths (`*1..N`) and paginate `/runs`/`/producers`.

Also worth recording: the `parent` facet hierarchy every `lineage-kit` adopter emits is parsed and discarded (`services/lineage/src/lineage/models.py:362-404`; no repository write), so job→stage→actor structure never reaches the graph; and a rename strands all version/schema/column history on the old vertex (`services/catalog/src/catalog/api/v1/endpoints/tables.py:788-857`, `repository.py:255`).
