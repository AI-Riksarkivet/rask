### [WRONG · high] The cascade's only built-in transform is an IMAGE deriver, in shared code, deployed live

Lance ships image handling only as opt-in extension arrays (`lance.arrow.ImageURIArray`/`EncodedImageArray`, guide.md:95-200), never inside the dataset writer. The estate's own ruling agrees: CLAUDE.md 'If an answer needs a modality's name, it belongs in a sealed runners/<workload>'; `schemas/htr.py` was deleted 2026-08-17 for 'making the cascade a transcription pipeline wearing a lakehouse's name' (medallion/schemas/tier.py docstring).
* **We do** — services/medallion/src/medallion/services/derivers.py:82 `_DERIVERS = ((media.is_image, _image_artifacts),)` — the ONLY registered deriver; packages/service-kit/src/service_kit/lakehouse/media.py:26-33 PIL `Image.MAX_IMAGE_PIXELS`, THUMBNAIL_COLUMN/EMBEDDING_COLUMN, EMBEDDING_DIMS=8 'deterministic pixel features — no ML model'; scripts/ray_stage_job.py:164-191, 280-290 same deriver on the Ray lane; chart/values.yaml:1358 media-to-silver `requiredColumns: "id,thumbnail,embedding"`; LIVE: deployment rask-media-to-silver env MEDALLION_REQUIRED_COLUMNS=id,thumbnail,embedding, MEDALLION_OPERATION=derive_media, no MEDALLION_TRANSFORM set (default deriver runs). docs/DECISIONS.md:113-118 records the PLAN to grow this: 'Real-encoder deriver ... slots in as a `_DERIVERS` plugin' and 'Additional-modality derivers — audio/video/pdf slot into `_DERIVERS`'.
* **Why it matters** — Apply the estate's own test — 'would this be right for audio?': for audio the cascade is an identity stamp (silver == bronze + stage), for images it is a fixed PIL pipeline. That is a transcription-shaped lakehouse with the noun changed to 'image'. The recorded §9 plan (more modalities INTO `_DERIVERS`) is the exact design the 2026-08-17 ruling rejected, so the recorded reason does not survive the later ruling. The TransformSpec/task_registry seam (transform_spec.py, transform_specs.py, task_registry.py) and runners/dummy already show the correct shape and are unused by the live media lane.
* **Fix** — Move `_image_artifacts` + `service_kit.lakehouse.media` into a sealed runner (runners/dummy's SILVER_SCHEMA + transform_batch is the template), register it under `<control_root>/_tasks/`, declare media-to-silver as a TransformSpec, and set MEDALLION_TRANSFORM on the mover. ### [WRONG · high] Cascade-produced vectors are invisible to the estate's own search and indexed by nothing — the glue is missing, not the type

* **Lance says** — FixedSizeList is 'the recommended type for storing fixed-dimensional vector embeddings' (guide.md:989-991); production search wants `create_index("vector", index_type="IVF_PQ", ...)` then `nearest={...}` (guide.md:1110-1131). The Namespace spec exposes CreateTableIndex/CreateTableScalarIndex/DescribeTableIndexStats/DropTableIndex (ns_catalog/spec.yaml:1690-1856) and 'index creation is handled asynchronously'.
* **We do** — The platform writes a FixedSizeList `embedding` (derivers.py:73-76; runners/dummy transform.py:52) but never indexes it: `create_index(` appears only behind the catalog door (catalog/api/v1/endpoints/indices.py:69) and its queue worker (maintenance/services/index_build.py:102) — no cascade, mover or ingest path publishes an IndexWorkItem for a vector column. services/search resolves targets ONLY from a `lance_media.descriptor` schema-metadata stamp (service_kit/lancekit/descriptor.py:32; search/services/target.py:1-10 'all corpus knowledge flows from the descriptor'); the only writers of that stamp are scripts/seed_demo_corpus.py:333 and runners/diarize + runners/voiceprint dataset.py — neither ingest/lander.py, medallion/compute.py nor ray_stage_job.py stamps one. search/services/constants.py:13-16 assumes an IVF index ('Ignored when the column has no IVF index'). DECISIONS.md:110-112 already records 'Catalog registration of cascade outputs — not registered'.
* **Why it matters** — This is the honest answer to 'is agnosticism costing multimodal capability': no — the payload is a real blob and the derived column is a real vector, so the format is not being fought. What is missing is one declaration hop: the transform's output never tells the catalog which columns are searchable, so a governed silver table with a vector column is a Lance table Lance could search and rask cannot. The 8-dim demo vector also means nothing has ever exercised an IVF build over cascade output.
* **Fix** — Make search bindings part of the TransformSpec / runner output contract (vector column, dim, query_encoder key, fts column), have the catalog PUBLISH door — 'the ONLY door' per medallion-data-flow.md §4 — stamp `lance_media.descriptor` from that declaration and enqueue an IndexWorkItem (VECTOR_INDEX / INVERTED) for each declared column, keeping the recall gate DECISIONS §9 already requires before an ANN index is trusted.

* **Lance says** — Data evolution: 'backfill existing rows with the new column data without rewriting the data files' via `add_columns` with a UDF (guide.md:606-716), distributed by `lance_ray.add_columns(uri, transform=..., concurrency=N)` (lance_docs/ray.md:140-150, 655-665). `lance_ray.write_lance` accepts `initial_bases`, `target_bases`, `external_blob_mode` ('reference' stores external references) and `allow_external_blob_outside_bases` (ray.md:815-871) — CONFIRMED on the installed lance_ray 0.5.0 `write_lance` signature, which also exposes `add_columns` and `merge_columns_from`.

* **Fix** — Measure, then delete: write a blob-v2 table through lance_ray 0.5.0 `write_lance(external_blob_mode="reference", initial_bases=[...])` and check the `lance.blob.v2` extension survives. ### [WRONG · med] The governed-tier contract is name-only for `stage` and `lineage`: the platform writes JSONB, a sealed runner writes string, and the publish door passes both

* **Lance says** — `pa.json_()` is stored as JSONB and is what makes `json_get_*`/`json_extract` filters and the JSON scalar index work (guide.md:1813-1820, 2014-2044); a plain string column has none of that.
* **We do** — service_kit/lakehouse/stage_stamp.py:114 stamps `lineage` as `pa.json_()`; runners/dummy/src/dummy_runner/transform.py:49 declares `pa.field("lineage", pa.string())` and says it 'SATISFIES the contract rather than importing it, and the catalog's publish door is the authority that refuses a tier which does not'. That door, service_kit/lakehouse/quality.py:58-108 `tier_contract_violations`, checks presence of the three names and the uint64 width of `source_rowid` only — no type check on `stage` or `lineage`. compute.py:248-262 builds the JSON scalar index on `lineage`, which cannot exist on the string variant.
* **Why it matters** — The tier contract is the ONE thing the platform is allowed to know about a governed row, and it is exactly the seam a sealed runner is told it will be refused at. Today the same column name lands with two Arrow types depending on who wrote it; a consumer filtering `json_get_string(lineage,'run_id')` works on platform-written silver and errors on runner-written silver.
* **Fix** — Extend `tier_contract_violations` to assert `stage` is string and `lineage` is `pa.json_()` (or accept string and cast at publish), and have runners/dummy's SILVER_SCHEMA use `pa.json_()`. Pin with a test that writes both shapes through the publish door.

### [WRONG · high] Branch creation is owner-gated, inverting the isolation model that is the whole point of Lance branches

* **Lance says** — Lance tracks branches by ROOT: a branch's manifests, data, deletions and indices all live under `tree/<branch>/` and a branch write never touches main's metadata (lance_docs/file_format.md:2742-2778 'Branch Dataset Layout'; lancemultibasebranchingblobv2.md:355-431 'no perf bottleneck … strong governance isolation (branch data physically under tree/<branch>/, so storage ACLs can be read-only on main and write-only on the branch)'). The SDK describes branches as 'isolated, writable lines of history forked from another branch… Writes on a branch do not affect main' (lance_sdk.md:456).
* **We do** — `define can_create_branch: owner` with the comment 'A plain data WRITER appends/overwrites within the current line; FORKING history (branch/tag) … is privileged' (packages/service-kit/src/service_kit/governed/auth/model.fga:353-357), pinned by model.fga.yaml:264 ('forking history is privileged') and :573-592 (writer dave DENIED can_create_branch, ALLOWED can_write_data); routed at services/catalog/src/catalog/api/fga_deps.py:98-108 ('branches/create': 'can_create_branch' in the OWNER suffix map). * **Fix** — Lower `can_create_branch` to the writer rung (or project member) and add the model the estate's own plan already names (open_lakehouse_diff_left.md R5/C2): `type branch { parent: [table]; reader/writer; can_write_data }`, credential vending scoped to `tree/<branch>/`, per-branch protection/trash.
